# numo-web: conventions

Next.js 16 (App Router, TypeScript, **ESM**) web app for NuMo. Local-only for now. Setup and commands: see `README.md`.

## Workflow

- Everything is in **English**: code, comments, issues, commits, PRs.
- Branches: Conventional Branch, `<type>/<issue-number>-<slug>` (e.g. `feature/12-create-account`, `bugfix/…`).
- Commits: `#<issue-number>: <description>`.
- GitFlow: work branches start from and target `develop` (the default branch); only `release/*` and `hotfix/*` go to `main`. One commit per PR, except `release/*` → `main` and `main` → `develop`. CI enforces branch names and commits (`validate-branch`, `validate-commit`).
- Releases: `release/x.y.z` from `develop` with the bumped `version`, PR into `main`, merged with a **merge commit**; CI tags it `tag_v-<version>.<YYYYMMDDHHMM>` and opens a `main` → `develop` sync PR, also merged with a merge commit (see `README.md`).
- `.github/scripts/` is copied from `numo-api` (kebab-case names kept to match it): change both repos together.
- This repo is public: don't reference other private projects in code, commits or PRs.

## Tooling

- **Yarn 4 only** (Corepack, `packageManager`); never npm, never commit `package-lock.json`.
- Node 26 (`.nvmrc`). Corepack must be installed separately (`npm install -g corepack`).
- Dev server runs on port **3001** (`numo-api` owns 3000); `yarn test:e2e` starts its own on **3002**.
- Before handing work over: `yarn format:check && yarn lint && yarn typecheck && yarn test:cov && yarn build && yarn test:e2e` must pass (80% coverage).
- Never bypass the pre-commit hook (`--no-verify`).
- Next.js 16 may differ from what you remember: check the docs bundled in `node_modules/next/dist/docs/` before using an API, and heed deprecation notices.

## Architecture (Clean Architecture, by feature)

- `src/app/` holds **routes and layouts only**: thin files that compose feature UI. No business logic, no data fetching details.
- Features live in `src/features/<feature>/` (mirroring `numo-api` modules), with only the layers they need:
  - `domain/`: types and pure business rules (no React, no Next, no fetch).
  - `application/`: use cases / orchestration hooks depending on ports.
  - `infrastructure/`: `numo-api` clients and DTO → domain mapping. Clients are **server-only** (`import 'server-only'`) and call `NUMO_API_URL` (server-only env, default `http://localhost:3000`) server to server; the browser reaches them through Server Actions (`'use server'`, e.g. `authActions.ts`). Never call `numo-api` from the browser. There's no `/api` proxy.
  - `ui/`: components.
- Dependency rule: `ui`/`infrastructure` → `application` → `domain`.
- **Session:** after sign-in, numo-api's tokens live only in the `numo_session` cookie (`auth/infrastructure/sessionCookie.ts`): JWE `dir` + `A256GCM` under `SESSION_SECRET` (server-only, ≥ 32 bytes, checked on use), HttpOnly, Secure, `SameSite=Lax`. A Server Action's return value reaches the browser, so it never carries a token, and numo-api's `refresh_token` cookie is never forwarded. Specs that use `jose` run in Node (`// @vitest-environment node`): under jsdom it rejects Node's `Buffer` keys.
- `src/shared/` only for code a **second** feature actually needs. No empty folders or abstractions "for later".
- Import across folders with the `@/*` alias (`@/features/accounts/domain/money`).

## UI conventions

- One camelCase folder per component: `ui/topbar/Topbar.tsx` + `Topbar.spec.tsx`.
- `.tsx` files are PascalCase, `.ts` files camelCase.
- State and effects go in a companion `useX.ts` hook, so the component file is JSX only.
- Prefer presentational components (props in, JSX out). Keep `"use client"` at the leaves.

## UI kit (gluestack-ui v4)

- Build screens from **gluestack-ui v4** components (NativeWind 4 + Tailwind CSS 3, rendered through `react-native-web`). Not v5: it dropped Next.js support.
- Add a component only when a screen needs it: `yarn dlx gluestack-ui@3.0.12 add <name> --use-yarn --path src/components/ui` (the `3.0.12` CLI is the v4 line). Import it as `@/components/ui/<name>`.
- `src/components/ui/**` is **vendored** (generated by the CLI): don't hand-edit it, and it's excluded from lint, Prettier and coverage. It's exempt from the one-folder-per-component naming rule.
  - **Exception: `gluestack-ui-provider/config.ts`** holds the theme: the NuMo design system's colors (light and dark), copied as RGB triples into gluestack's `--color-<name>-<step>` slots. Keep it in sync with the design system. The CLI can overwrite it on `add`, so check its diff afterwards and restore the NuMo values.
- gluestack, NativeWind, Tailwind and the React Native packages are pinned to **exact** versions (no `^`/`~`): the stack breaks on minor updates, so upgrade them together and on purpose. `react-native-web` is `0.21.x` because older lines don't support React 19.
- Wiring, and why:
  - `next.config.ts` uses `withGluestackUI` but drops its `webpack` key, because Next 16 builds with Turbopack and refuses to build when a webpack config is present.
  - `tsconfig.json` sets `jsxImportSource: nativewind`, so `className` styles React Native components.
  - `src/app/registry.tsx` flushes react-native-web styles during SSR, and the root layout wraps the app in it and in `ThemeModeProvider` (which renders `GluestackUIProvider`; see "Theme and brand").
  - Tailwind/PostCSS configs are `.cjs` because the repo is ESM.
- Vitest (`unit` project) aliases `react-native` → `react-native-web`, resolves `.web.*` files first, and swaps `nativewind` for [`src/testing/nativewindStub.ts`](src/testing/nativewindStub.ts) with React's own JSX runtime. It also swaps `server-only` for an empty [`src/testing/serverOnlyStub.ts`](src/testing/serverOnlyStub.ts) (Next.js resolves it itself). NativeWind's runtime only compiles inside an app bundler. Unit tests check structure and roles; styling is checked by Playwright.
  - `react-native-safe-area-context` is aliased to its ES-module build: its CommonJS build `require`s `react-native` through Node, past Vite's alias. Another React Native package failing with `Cannot find module 'react-native'` needs the same fix.
- Form-field quirks (see `LabeledInput` in `src/features/auth/ui/signInForm/`):
  - every `FormControl` gets the same generated id and every `InputField` the aria-label "Input Field", so pass `id` and `aria-label` explicitly;
  - `@types/react-native` predates `autoComplete` tokens like `current-password`, which react-native-web passes straight to HTML: cast at that one prop.
  - A gluestack `Button` is a `div role="button"`: disabled shows as `aria-disabled="true"`, not `disabled`.

## Theme and brand

- **Colors come from tokens only**: classes like `bg-background-0`, `text-typography-900`, `border-outline-200`, `bg-primary-500`; never hex values. Tokens switch with the theme. The one exception is the logo mark (`src/shared/ui/logo/`), whose brand colors stay fixed on light and dark (logo sheet: "On dark").
- **Dark mode** is the `.dark` class on `<html>` (Tailwind `darkMode: 'class'`).
  - `ThemeScript`, an inline `<head>` script, applies the saved choice (`localStorage.theme`) or the OS preference **before the first paint**.
  - `ThemeModeProvider` adopts that class and passes it to `GluestackUIProvider` as `mode`. Never hardcode `mode`: the provider rewrites the class on `<html>` from it.
  - `<html suppressHydrationWarning>` exists only for that class.
- **Font:** Plus Jakarta Sans through `next/font` (`--font-plus-jakarta-sans`, Tailwind's `sans`). react-native-web forces the OS font on its text, so `globals.css` sets the family on `html [dir='auto']`: gluestack text needs no font class.
- **App frame:** pages in the `src/app/(shell)/` route group get the top bar. Sign-in and sign-up live in `src/app/(auth)/`, without it, and show the centered logo in `AuthCard` instead.
- After moving or renaming a route, a stale `.next/` can make `yarn typecheck` fail with `Cannot find module '…/src/app/…'`: delete `.next/` (it's regenerated).

## Clean Code

- Intention-revealing names; small single-purpose functions (~20 lines), ≤ 3 args, no boolean flag args.
- Don't return or pass `null`; use `T | undefined`, empty collections or domain errors.
- Comments only for a non-obvious _why_; no commented-out code.
- Let Prettier/Oxlint decide style.

## Tests

- Vitest (jsdom, globals on) + Testing Library; tests next to the code as `*.spec.ts(x)`.
- Arrange–Act–Assert, one behaviour per test; query by role/label as a user would.
- Domain: pure unit tests. Hooks/use cases: fake clients. Components: Testing Library. User flows: Playwright.
- E2E: Playwright (Chromium), specs next to the route as `*.e2e.ts` (e.g. `src/app/page.e2e.ts`). Browsers: `yarn playwright install chromium`.
  - Import `test`/`expect` from `@/testing/e2eFixtures`, never from `@playwright/test`: its `page` fixture fails the test on any browser console error or uncaught page error.
  - Never call the real `numo-api`. Server-side calls (Server Actions) go to the `numoApi` fixture, an in-process mock `numo-api` on port 3998 ([`src/testing/numoApiMock.ts`](src/testing/numoApiMock.ts)): `numoApi.respond('POST /auth/register', reply)`, `numoApi.goDown(route)`, and `numoApi.calls` to assert what it received. An unmocked call answers `500` and fails the test with its method and path.
  - Every numo-api call is server-side, so the fixture aborts any browser request to `/api/` and fails the test. No fixed `waitForTimeout`; rely on auto-waiting assertions.
  - Query the app's alerts inside `<main>` (`page.getByRole('main').getByRole('alert')`): Next.js adds its own hidden `role="alert"` route announcer.
  - `yarn test:e2e` starts its own Next.js server on 3002 with `NUMO_API_URL` pointing at the mock, a test-only `SESSION_SECRET` and its own build directory (`NEXT_DIST_DIR=.next-e2e`, since Next.js locks `.next` while `yarn dev` runs), so it never reuses `yarn dev`. `CI=true yarn test:e2e` builds and serves the production build.
- Every new function gets a test; every bug fix gets a regression test.
